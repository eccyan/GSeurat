Camera State Blending Strategy

When transitioning between camera zones (e.g., free-look → rail), how should the system interpolate?

The Problem

  Volume A (Free Look)              Volume B (Rail Follow)
  ┌─────────────────┐    trigger    ┌─────────────────┐
  │                  │      │       │                  │
  │  cam @ (10,5,20) │──────┼──────→│  rail @ (30,8,15)│
  │  fov: 45°        │      │       │  fov: 60°        │
  │  pitch: -15°     │              │  pitch: -25°     │
  └─────────────────┘               └─────────────────┘

  Without blending: SNAP! Instant jump — nauseating
  With blending:    Smooth 1-2s interpolation of all parameters
A

Simple Lerp (Linear Interpolation)

Linearly blend all camera parameters over blend_time seconds.

t = elapsed / blend_time          // 0.0 → 1.0
pos = mix(old_pos, new_pos, t)
rot = slerp(old_rot, new_rot, t)
fov = mix(old_fov, new_fov, t)

  old ●━━━━━━━━━━━━━━━● new
      constant speed

Simple, predictable. Can feel mechanical/robotic on longer blends.

B

Eased Blend (smoothstep / ease-in-out)

Apply an easing curve to the blend factor. Starts slow, accelerates, then decelerates.

t = elapsed / blend_time
t = smoothstep(t)                 // 3t² - 2t³
pos = mix(old_pos, new_pos, t)
rot = slerp(old_rot, new_rot, t)

  old ●╌╌╌━━━━━━━━╌╌╌● new
      slow  fast  slow

Feels natural. Standard in AAA camera systems. Negligible extra cost (one multiply).

C

Spring Damper (Critically Damped)

Physics-based spring that naturally settles. No fixed blend time — converges asymptotically. Handles interruptions gracefully (re-targeting mid-blend).

// Critically damped spring (no oscillation)
omega = 2.0 / half_life
exp_term = exp(-omega * dt)
pos += (target - pos) * (1 - exp_term)

  old ●━━━━━╌╌╌╌╌╌╌╌╌╌ new
      fast     asymptotic approach

  Interrupted mid-blend? Just change target:
  old ●━━━╲
           ╲━━━━╌╌╌╌╌ new_target

Most robust for gameplay (handles rapid zone changes). Slightly harder to tune. No "done" signal — needs threshold.

Recommendation: B + C Combined

Use eased blend (B) as the default for designed transitions (volume enter, explicit triggers) where blend_time is authored. Use spring damper (C) for the "follow" component — the per-frame smoothing of the camera tracking its target position. This matches industry practice:

  • Zone transition: smoothstep blend over authored blend_time (predictable, art-directed)
  • Within a zone: spring damper for target tracking (responsive, handles interrupts)

The spring damper already exists in your codebase — Camera::smooth_follow() uses exponential smoothing, which is mathematically equivalent to a critically damped spring with half_life = ln(2) / smoothing_factor.
