Camera Trigger Geometry

How should the system detect when to transition between camera zones? Triggers fire when the player character (not the camera) crosses them.

A

Volume Overlap (Implicit Triggers)

No separate trigger objects. Camera volumes overlap at boundaries. When the player enters a new volume, the system transitions to its rules. Priority resolves conflicts (smallest volume wins, or explicit priority field).

  +----------+----------+
  | Volume A |          |
  |          | overlap  |  Volume B
  |   cam ---+--> cam   |
  |          |          |
  +----------+----------+

  Player in A only  → A rules
  Player in A ∩ B   → highest priority wins
  Player in B only  → B rules

Pros

  • Simpler data model (no extra entities)
  • Volumes ARE the triggers
  • Easy to reason about spatially

Cons

  • Overlapping volumes can get confusing
  • Less control over exact transition point
  • Priority system needed for conflicts
B

Explicit Trigger Volumes (Separate Entities)

Thin volumes (or planes) placed at doorways/transitions. Each trigger references a "from" and "to" camera zone. Fires on player enter. Directional triggers possible.

  +----------+ | +----------+
  | Volume A | T | Volume B |
  |          | r |          |
  |   cam ------> cam      |
  |          | g |          |
  +----------+ | +----------+
               ^
          thin trigger volume
          (links A → B)

Pros

  • Precise control over transition point
  • Directional (A→B vs B→A can differ)
  • Clean separation: volumes define rules, triggers define transitions

Cons

  • More entities to place in editor
  • Possible to create orphaned triggers
  • More complex data model
C

Hybrid (Recommended)

Volumes auto-trigger on player enter (like A), BUT explicit triggers can override behavior at specific boundaries. Best of both: simple cases stay simple, complex transitions get precision.

  +----------+   +----------+
  | Volume A |   | Volume B |   Implicit: enter B → B rules
  |          |   |          |
  +----------+   +----------+

  +----------+ | +----------+
  | Volume C | T | Volume D |   Explicit: trigger overrides
  |          | r |          |   blend time, can be directional
  +----------+ | +----------+

  Default: volume enter/exit = trigger
  Override: place explicit trigger for special behavior

Pros

  • Simple cases need zero trigger placement
  • Complex cases get explicit control
  • Matches RE/FF camera system patterns
  • Explicit triggers are optional — progressive complexity

Cons

  • Two code paths (implicit + explicit)
  • Slightly more complex state machine
