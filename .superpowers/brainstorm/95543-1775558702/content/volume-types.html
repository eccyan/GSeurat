Boundary Volume Types

Which shapes should camera volumes support? These define the 3D regions where camera rules apply.

1

Axis-Aligned Box (AABB)

Simple box defined by min/max corners. Fast intersection test (6 comparisons). Cannot rotate — always aligned to world axes. Good for rectangular rooms and corridors.

   +--------+      center: [32, 5, 20]
   |        |      half_extents: [10, 5, 8]
   |   cam  |
   |    .   |      Contains test:
   |        |      abs(p - center) <= half_extents
   +--------+      (per-axis, 6 comparisons)
2

Oriented Box (OBB)

Box with arbitrary rotation. Slightly more expensive intersection (transform point to local space first). Fits angled corridors and tilted buildings.

      /------/|     center: [32, 5, 20]
     / cam  / |     half_extents: [10, 5, 8]
    /   .  /  |     rotation: [0, 45, 0]
   +------+   |
   |      |  /     Contains test:
   |      | /      p' = inverse(rot) * (p - center)
   +------+/       abs(p') <= half_extents
3

Sphere

Defined by center + radius. Cheapest test (single distance check). Natural for open areas, arenas, plazas.

      ___
    /     \        center: [32, 5, 20]
   |  cam  |       radius: 15.0
   |   .   |
    \_____/        Contains test:
                   length(p - center) <= radius
                   (1 sqrt or compare squared)
4

Cylinder

Vertical cylinder: center + radius + height. Good for towers, wells, vertical spaces. XZ circle test + Y range check.

     ___
    / . \  cam     center: [32, 0, 20]
   |     |         radius: 10.0
   |     |         height: 12.0
   |     |
    \___/          Contains test:
                   length(p.xz - c.xz) <= r
                   AND p.y in [c.y, c.y+h]

Recommendation

Start with AABB + Sphere (covers 90% of use cases with minimal code). OBB and Cylinder can be added later since the volume interface is polymorphic — same contains() / clamp() API regardless of shape. Click all that you want in Phase 1.
